# 用 SSA 接口转换点和类型契约替换自研值流分析

## 背景与问题

ripples 需要把接口方法的动态调用和具体实现的变化连接起来，否则修改某个实现后，使用它的 binary 不会出现在结果中。原实现在 `internal/impact/symbol.go` 中用约两千行自研值流解析，沿赋值、参数、返回值、字段和容器追踪具体类型，再把追踪到的接口调用连接到实现。

在临时仓库中复现后发现两类问题：

- 漏报：setter 注入、functional options、本地注册表、嵌入接口字段，以及经 `any` 参数触发的 `fmt.Stringer`、`json.Marshaler` 调用都追踪不到，注入这些实现的 binary 不会被报出。
- 性能：解析递归展开被调函数且没有记忆化，复杂度随调用深度指数增长。`github.com/google/go-cmp` v0.7.0 和 ripples 自身运行 40 分钟以上仍未完成。

## 决策驱动因素

- 结果用于 CI 选择测试和部署，漏报的代价远高于多报。
- 分析时间必须可预测，不能因代码形状出现指数爆炸。
- 优先使用标准库和 `golang.org/x/tools` 官方包，减少自研分析代码。
- 保持声明级粒度，不退化为按 import 传播。

## 考虑过的方案

- A：保留自研值流，增加记忆化，并在解析不到候选类型时回退到 CHA/RTA 风格的保守集合。
- B：用 `golang.org/x/tools/go/callgraph/vta` 生成调用图，把动态调用边映射回声明。
- C：用 `golang.org/x/tools/go/ssa` 找出所有 `MakeInterface` 转换点，让执行转换的声明依赖被转换类型的契约（方法集、字段布局和嵌套命名类型的契约）；实例化泛型的声明依赖类型实参的契约；函数值按静态引用处理。

## 决策结果

最终选择 C，因为具体值只有先转换为接口才能被动态调用，把依赖挂在转换点上不需要追踪接口值之后的流向，覆盖所有流动形式且复杂度线性，并且完全基于官方 SSA 和 `go/types`。

### 正面影响

- setter、functional options、本地注册表、嵌入接口字段、`fmt`/`encoding/json` 等动态调用全部可以传播，回归用例见 `internal/impact/interface_flow_test.go`。
- 分析时间与代码规模线性相关：go-cmp 冷缓存 0.67 秒，ripples 自身 0.98 秒；x/crypto 在同时分析测试文件的情况下为 2.1 秒，与旧版不含测试时的 2.17 秒持平。
- 删除约两千行自研值流代码，新增实现集中在 `internal/impact/contract.go`，约 300 行。
- 不同转换点互不混合：两个 binary 注入同一接口的不同实现时，修改其中一个只影响注入它的 binary。

### 负面影响

- 转换点依赖类型的全部方法。接口没有声明、代码也没有调用的方法发生变化时，同样会传播到转换点。
- 函数值不追踪流向，引用函数即依赖它，即使该函数值之后没有被调用。
- 结果报出做转换的包，不再报出只通过接口调用、自身代码没有变化的包。例如 `runner.Run(s Service) { s.Run() }` 所在的 `runner` 不再出现，影响落在注入实现的 `main` 上。
- 旧测试中编码调用点级精度的期望被改写；4 个函数值精度用例合并为 1 个，4 个"未使用方法或丢弃的转换不传播"用例合并为 1 个。
- 冷分析需要额外构建本地 package 的 SSA，内存高于只做类型检查。

## 各方案取舍

### A：自研值流加记忆化和保守回退

- 优点：保留调用点级精度，改动范围最小。
- 缺点：每种值流形式都要单独补齐，未覆盖的形式就是新的漏报来源；回退集合需要自己实现 CHA/RTA；记忆化需要设计与绑定集合相关的缓存键，复杂度难以证明；继续维护两千行自研分析，不符合优先使用官方库的要求。

### B：VTA 调用图

- 优点：官方实现，能处理字段、容器和函数值的流动。
- 缺点：VTA 为每个局部变量、字段和容器元素建立全局节点，与调用上下文无关。共享 helper（如 `retry.Do(f)`、HTTP 中间件）的参数一旦汇聚多个调用方的类型，所有调用方都会连到全部实现，结果接近全量传播。包文档标注仍处于实验阶段，接口可能变化。

### C：SSA 转换点和类型契约

- 优点：覆盖所有转换形式；线性复杂度；只依赖官方 SSA 和 `go/types`；影响自然落在做转换的声明上，保持上下文独立。
- 缺点：见负面影响，主要是方法级和函数值级的精度下降。
